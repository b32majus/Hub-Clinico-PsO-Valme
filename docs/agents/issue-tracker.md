# Issue tracker: GitHub

Issues/specs for this repository live in GitHub under `b32majus/Hub-Clinico-PsO-Valme`.

Use repository-native GitHub issue/PR tooling from the current clone. Resolve a bare `#N` as issue or PR rather than assuming from the number alone.

## Conventions

- accepted issue/WO is execution authority for the bounded change;
- verify issue state/body/comments live before execution when they can affect scope;
- do not reuse an issue from another scope as PR authority;
- issue/review completion does not grant merge/deploy authority;
- historical train issues may preserve old C-077/C-080 execution recipes; under C-083 only their product requirements/evidence remain potentially authoritative.

## Pull requests as a triage surface

**PRs as a request surface: no.**

A PR is a delivery/review surface for accepted work, not a substitute feature request.

## When a Matt skill says "publish to the issue tracker"

Create/update the appropriate GitHub issue only within explicit repository/human authorization.
